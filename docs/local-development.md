# Плеер на iOS и Android

Для оболочек нужны Node.js 22.11 или новее и зависимости из корня проекта (`npm ci`). Из корня проекта выполняются проверка типов (`npm run type-check`) и тесты адаптеров плеера (`npm test`).

На iOS нужны Xcode с установленным симулятором и CocoaPods. Выполните `pod install` в `ios/`, затем запустите `npm start` в корне и `npm run ios` во втором терминале.

На Android нужны JDK 17, Android SDK с платформой API 37, NDK 27.1.12297006 и запущенный эмулятор. Укажите путь к SDK через `ANDROID_HOME` или `android/local.properties`. Запустите `npm start` в корне и `npm run android` во втором терминале. Gradle Wrapper загрузит Gradle при первом запуске.

Для тестового экрана сборка Rust не требуется. В отладочной сборке внизу экрана есть панель «Тестовые состояния». Кнопка «Запуск с таймером на 5 с» переводит плеер в воспроизведение, затем в затухание и паузу. Смена сцены обновляет её ручки. Правки TypeScript и JSX видны через Fast Refresh при работающем Metro.

Проверьте экран в узкой и широкой области, с увеличенным системным текстом, с VoiceOver и TalkBack. На Android проверьте нижний отступ с жестовой и кнопочной навигацией. Основные действия должны быть доступны при прокрутке и с экранным диктором.

## Синтез на устройстве

На iOS установите Rust-цели `aarch64-apple-ios` и `aarch64-apple-ios-sim`. Выполните `npm run core:ios` в корне, затем `CUDDLE_LAMP_NATIVE_AUDIO=1 pod install` в `ios/`. После этого запустите обычную сборку iOS. Нативный XCFramework содержит срезы для устройства и симулятора на Apple Silicon. Для установки на iPhone выберите команду подписи для цели `CuddleLamp` в `ios/CuddleLamp.xcworkspace`. Для возврата к тестовому плееру повторите установку Pods без переменной.

На Android для нативного звука нужен API 26 или выше. Установите `cargo-ndk` и Rust-цели `aarch64-linux-android`, `armv7-linux-androideabi`, `i686-linux-android` и `x86_64-linux-android`. Соберите ядро командой `npm run core:android` и запустите `CUDDLE_LAMP_NATIVE_AUDIO=1 npm run android`. Для возврата к тестовому плееру запустите сборку Android без переменной.

### Проверка на симуляторе и устройствах

1. В тестовой сборке откройте каждое из пяти состояний с панели и запустите короткий таймер. Измените текст заголовка в TypeScript и проверьте, что Metro обновляет экран без пересборки оболочки.
2. В сборке со звуком по очереди запустите три встроенные сцены. Во время воспроизведения смените сцену и отрегулируйте ручку. Проверьте, что слышимое изменение соответствует сцене и значению на экране.
3. Установите таймер кнопкой «5 с для проверки» в отладочной сборке со звуком. Поставьте плеер на паузу до истечения таймера, дождитесь окончания затухания и убедитесь, что остаток больше не уменьшается. Продолжите воспроизведение и дождитесь затухания по таймеру. В ядре это затухание занимает до 20 секунд.
4. На физическом устройстве установите тот же таймер и заблокируйте экран. Проверьте системные команды на экране блокировки и окончание таймера при свёрнутом приложении. После разблокировки сравните надпись о состоянии с фактическим воспроизведением.
5. Проверьте прерывание звонком и отключение наушников. На Android также проверьте временную потерю и возврат аудиофокуса при воспроизведении звука другим приложением. Повторите сценарий с ручной паузой во время прерывания и проверьте, что плеер остаётся на паузе.

Проверки ядра, контракта и каталога выполняются командой `cargo test --workspace` в `core/`. Сборка веб-студии выполняется командой `npm run build` в `studio/`.

В отладочной сборке со звуком внизу плеера есть раздел «Импорт из студии». Вставьте туда экспортированный JSON и нажмите «Загрузить сцену». Плеер передаст исходный текст в тот же вызов Rust, что и для встроенных сцен. После подтверждения сцена появится в каталоге до перезапуска приложения. Если её идентификатор уже есть в каталоге, импортированная сцена заменит соответствующую запись на время проверки.

## Подготовка macOS и Windows

Мобильный проект использует React Native 0.87.1. На момент сверки стабильный выпуск macOS 0.83 основан на React Native 0.83.10, а стабильный выпуск Windows 0.85 основан на React Native 0.85.3. Совместимость этих выпусков с мобильной версией не подтверждена. Перед подключением оболочек нужно повторно сверить выпуски и подобрать зависимости отдельно для каждой настольной платформы. [Выпуски macOS](https://github.com/microsoft/react-native-macos/releases) · [Выпуски Windows](https://github.com/microsoft/react-native-windows/releases)

Код управления движком в `cpp/SoundEngineControl.cpp` компилируется без заголовков React Native. При подключении настольной оболочки её модуль Codegen может использовать этот файл вместе с тем же C API ядра.
